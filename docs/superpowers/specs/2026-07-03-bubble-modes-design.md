# 홈 버블 두 모드 (칼로리 ↔ 탄단지) — 설계

작성일: 2026-07-03
상태: 승인됨 (구현 대기)

## 배경 / 목적

현재 홈 화면의 버블 그릇은 음식 하나를 탄·단·지 **최대 3개 버블로 분리**해 각 매크로 색으로,
그 매크로의 칼로리 크기만큼 렌더한다. 신규 사용자에게는 다소 분석적이고 복잡하다.

"음식 1개 = 버블 1개"로 보여주는 **칼로리 모드**를 새 기본값으로 두고, 기존 탄·단·지 분리
뷰는 토글로 전환할 수 있게 해 사용자층을 나눈다.

- 신규/일반 사용자: 직관적이고 예쁜 "음식=버블" 뷰 (칼로리 모드)
- 영양을 파고드는 사용자: 탄·단·지 분리 뷰 (기존 동작)

## 출시 맥락

앱은 이미 App Store 출시·라이브 상태이며, 본 작업은 **업데이트**다. 앱이 원격 URL(Cloudflare)
모드이므로 웹 배포만으로 기존 사용자에게 반영된다(새 바이너리 불필요). 다만 홈 core 화면
변경이므로 배포 전 충분한 테스트가 필요하다.

## 동작 명세

### 두 모드 비교

| 항목 | 칼로리 모드 (신규 기본) | 탄단지 모드 (기존) |
|---|---|---|
| 버블 단위 | 음식 1개 = 버블 1개 | 음식 1개 = 탄·단·지 최대 3버블 |
| 버블 크기 | 음식 **총칼로리** 기준 | 각 매크로 칼로리 기준 |
| 버블 색 | `KCAL_PALETTE` 10색, **음식 이름 기반 고정 배정** | 매크로 색(탄/단/지) |
| 버블 텍스트 색 | 팔레트 항목의 `text` 값 | 기존 규칙(carbs=#333, else #fff) |
| 버블 탭 | 그 음식 삭제 | 그 음식 삭제 (기존과 동일) |

### 전환 & 상태 기억

- **토글 UI:** 버블 그릇 바로 아래 중앙(“버블을 탭하면 제거됩니다” 안내 근처)에
  세그먼트 컨트롤 `[칼로리 | 탄단지]`.
- **기본값:** 저장된 선택이 없으면 **칼로리 모드**.
- **기억:** 마지막 선택을 `localStorage`에 저장하여 재실행·재방문 시 유지.
  - 키 예: `tandanji_bubble_mode`, 값: `"kcal" | "macro"`.

### 공통 규칙 (모드 무관)

- **0칼로리 음식:** 두 모드 모두 그릇(BubbleField)에는 안 뜨고 슬롯 목록(MealLogList)에만
  표시. 현재 규칙(2026-07-03 수정: grams 0 placeholder 엔트리 + BubbleField가 grams>0만 렌더)을
  그대로 유지·확장한다. 칼로리 모드에서도 "총칼로리 0"인 음식은 그릇에 안 뜬다.
- **그릇 stage(과식 경고), 진척바, 상단 탄·단·지 요약 수치:** 모두 총칼로리·매크로 합계
  기준이라 모드와 무관하게 동일하게 동작한다.
- **색 일관성:** 홈 칼로리 모드와 기록(history) 탭이 동일 팔레트를 공유하므로 같은 음식은
  어디서든 같은 색으로 보인다.

## 구현 구조

### 신규: `src/lib/kcalPalette.ts`

history.tsx에 로컬로 존재하는 아래를 추출해 공용 모듈로 만든다.

- `KCAL_PALETTE: { color: string; text: string }[]` (주얼톤 10색)
- `hash01(name, seed)` — 결정적 해시 (history.tsx에서 이동/공유)
- `kcalPaletteEntry(name): { color, text }`
- `kcalBubbleColor(name): string`
- `kcalBubbleText(name): string`

history.tsx는 이 모듈에서 import하도록 변경(동작 동일, 중복 제거).

### 변경: `src/routes/index.tsx`

- 모드 state 추가: `const [bubbleMode, setBubbleMode] = useState<"kcal" | "macro">(...)`,
  초기값은 localStorage에서 로드(없으면 `"kcal"`). 변경 시 localStorage에 저장.
- `logsToBubbles(logs, mode)`에 모드 분기:
  - `macro` 모드: 기존 로직 그대로(매크로별 엔트리 + 0칼로리 placeholder).
  - `kcal` 모드: 음식(log)당 엔트리 1개. 크기는 총칼로리, 색/텍스트색은
    `kcalBubbleColor/Text(foodName)`. 총칼로리 0이면 placeholder(그릇 미표시, 목록만).
- `BubbleEntry`에 선택적 필드 3개 추가(확정 방식):
  - `color?: string` — 지정 시 버블 배경색으로 사용.
  - `textColor?: string` — 지정 시 라벨 텍스트 색으로 사용.
  - `sizeKcal?: number` — 지정 시 반지름 계산에 이 총칼로리 값을 사용.
- 칼로리 모드 엔트리는 위 3개를 모두 채운다(`macro`는 타입상 필요하나 색·크기 계산에는
  쓰이지 않음 — `color`/`sizeKcal`가 우선). 탄단지 모드 엔트리는 3개를 비워 기존 경로를 탄다.

### 변경: `src/components/BubbleField.tsx`

- 노드 색 결정: 엔트리에 `color`가 있으면 그 색을, 없으면 기존 `MACRO_COLORS[macro]` 사용.
- 노드 텍스트 색: 엔트리에 `textColor`가 있으면 사용, 없으면 기존 규칙.
- 반지름 계산: 엔트리에 `sizeKcal`이 있으면 그 값으로 `radiusForKcal` 호출,
  아니면 기존처럼 `grams * MACRO_KCAL[macro]`.
- grams>0(=칼로리>0) 필터 규칙 유지.

### 변경: 토글 UI (index.tsx 내)

- 그릇 아래, 기존 stage 안내 문구 영역 근처에 세그먼트 컨트롤 배치.
- 탭 시 `setBubbleMode` + localStorage 저장.

## 테스트 관점

- 칼로리 모드: 음식 1개당 버블 1개, 크기=총칼로리, 같은 음식 재추가 시 같은 색.
- 탄단지 모드: 기존과 동일하게 최대 3버블, 매크로 색.
- 토글 전환: 즉시 반영, 새로고침/재실행 후에도 마지막 모드 유지.
- 0칼로리 음식: 두 모드 모두 그릇 미표시 + 슬롯 목록 표시.
- 홈·기록 색 일관성: 동일 음식이 두 화면에서 같은 색.
- 그릇 stage/진척바/요약 수치: 모드 전환해도 동일.

## 범위 밖 (YAGNI)
